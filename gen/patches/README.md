# Source patches applied before generation

Applied by `gen/run_pilot.py --stage patch` through `apply_patches.py`; each is recorded in `logs/patches.json` with the file's sha256 before and after. Patches 1–4 change no computed value. Patches 5–6 are active only when `PILOT_TRANSFORMER_DTYPE=fp16` is set, which was the case for every pilot video; the dtype in force is written to every attempt log.

| id | file | change | why |
|---|---|---|---|
| dist-backend | `diffusers_helper/parallel_mgr.py` | `backend='nccl'` → `'nccl' if available else 'gloo'` | Lets the one-process group init run where NCCL is absent. Inactive on Linux. |
| lowvram-text-encode-1 / -2 | `inference_f1_json.py`, both prompt-encode sites | add `fake_diffusers_current_device(text_encoder, gpu)` and `load_model_as_complete(text_encoder_2, target_device=gpu)` inside `if not high_vram:` | The low-VRAM branch (free VRAM ≤ 60 GB) lacks two lines upstream FramePack has here; without them the prompt encode fails with `Expected all tensors to be on the same device`. The authors ran on ≥ 80 GB GPUs, where this branch is skipped. |
| sdpa-query-chunks | `diffusers_helper/models/hunyuan_video_packed.py`, SDPA fallback in `attn_varlen_func` | run `scaled_dot_product_attention` over query chunks of 512 on GPUs older than Ampere (`ATTN_Q_CHUNK` overrides) | The T4 has no fused bf16 attention kernel, so the fallback allocated the full score matrix (30 GiB). Each query row's softmax is independent, so chunking is exact. Inactive on sm_80+. |
| transformer-dtype-env | `inference_f1_json.py`, transformer load, `.to(dtype)` and the two `sample_hunyuan` calls | `torch.bfloat16` → dtype from `PILOT_TRANSFORMER_DTYPE` (default bf16) | The T4 emulates bf16 arithmetic (8358 s for one 2 s clip); fp16 runs on its tensor cores. The other four models are fp16 upstream already. |
| fp32-residual | `hunyuan_video_packed.py`, both transformer block forwards and the final norm | in fp16: keep the residual stream (hidden and text states) in fp32 across blocks, feed fp16 to attention and MLPs, compute the gated residual updates in fp32, return fp32 from the projections that write into the residual (MLP down-projections, single-block `proj_out`) via `torch.mm(out_dtype=float32)`, run the final AdaLayerNorm in fp32 | Plain fp16 produced a black clip. `gen/nan_probe.py` found the overflow in three places, in order: the residual stream entering block 7 (29760 hidden, 51328 text, fp16 max 65504), the block-7 gate × MLP product, and the output of block 19's text MLP down-projection. Everything else in a block is normalised and stays small. No effect in bf16. |
